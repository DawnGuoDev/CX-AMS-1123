# 警报详情 · 通知发送失败快速查看 PRD

在「警报详情」的「通知发送记录」中直接看到发送概况，并一键筛选失败通知；适用于即时警报汇总、处理／历史查询、设备模拟等所有可打开警报详情的入口。

## 功能需求

### REQ-001 查看通知发送概况并筛出失败记录

- 进入「警报详情 → 通知发送记录」时，记录区顶部显示发送总数、成功数、失败数、其他数，以及「全部 / 成功 / 失败」筛选，默认「全部」。「其他」为等待发送（`Pending`）与已取消（`Skipped`）之和，为用户提供「还有未完成发送」的感知，避免误认为全部发送已结束。
- 统计与筛选只作用于「通知发送记录」区，不影响基本资讯、详细内容、回应备注、交易履历、事件层级、回应记录，也不影响「刷新发送与确认状态」上方的事件层级与已回应人数。
- 选择「成功」只列出状态为 `Success` 的记录；选择「失败」只列出状态为 `Fail` 的记录，并突出显示失败状态与失败原因（现有「说明」列）。「其他」不作为筛选项，只作为统计提示。
- 失败原因超出显示宽度时，用户可展开查看完整内容；筛选或刷新后，已展开的内容可收起，不做跨操作保留。
- 切换到「失败」且当前没有失败记录时，记录区显示「暂无发送失败的通知」和「查看全部」入口；点击「查看全部」切回「全部」筛选及完整记录。
- 点击「刷新发送与确认状态」后，总数、成功、失败、其他、记录列表和空态提示一起更新，且保留当前「全部 / 成功 / 失败」筛选；不保留搜索词、列过滤等表格内临时条件。
- 关闭详情后再打开任一警报（含同一警报），筛选恢复为「全部」，且只展示该警报自己的通知记录。
- 本次不提供手动重发；原有警报确认流程、「刷新发送与确认状态」入口位置和其他页签行为保持不变。

### 统计与筛选口径

- 发送结果沿用现有四种状态：`Pending`（等待 SMTP 发送）、`Success`（SMTP 已接受）、`Fail`（发送失败）、`Skipped`（本层级已结束，取消待发送）。
- 统计中的「成功数」只包含 `Success`，「失败数」只包含 `Fail`，「其他数」包含 `Pending` 与 `Skipped`；总数 = 成功数 + 失败数 + 其他数。已确认口径（2026-11-26）：等待发送和已取消单独计数，不计入失败，也不因「失败」筛选被隐藏。
- 统计数始终按该警报的全部通知记录计算，不随当前筛选或表格内搜索／列过滤变化；「全部」筛选下的记录条数等于发送总数。
- 筛选结果为空时，不显示原表格的「查无资料」，改为对应提示；「全部」下无记录时显示「暂无通知发送记录」；「成功」下无记录时可用同款提示「暂无发送成功的通知」并提供「查看全部」。
- 历史交易详情为只读场景：发送次数、记录与当前筛选状态均按该历史时间点的数据展示，不提供刷新，行为与其他页签一致。

## 验收标准

- 一条向多人发送、部分失败的警报：打开详情即可看到总数 / 成功 / 失败 / 其他四个数字（总数等于三者之和）；点「失败」只留下失败人员，能辨识失败状态并展开完整原因；点「成功」只留下成功人员，「全部」恢复完整记录。
- 全部发送成功时点「失败」：出现「暂无发送失败的通知」，「查看全部」返回完整记录；刷新后仍停留在当前筛选，关闭再打开任意警报回到「全部」。

## 研发接续

- **前端**：`frontend/src/components/AlarmDetail.vue` 已具备通知记录明细（`RESULT`、`MESSAGE`、`SEND_DT`）、页签状态和刷新入口；需新增统计条（含「其他」）、筛选状态、失败原因展开和空态。`.vue` 中已有 `RESULT` 状态标签配色与 `destroy-on-close` 弹窗，可复用。
- **前端缺口**：记录表 `frontend/src/components/DataGrid.vue` 为单元格设置 `white-space: nowrap`、无展开机制，长失败原因现被截断；需为失败原因提供展开／收起。表格自带搜索与列过滤会保留对当前子集的筛选，PRD 要求刷新后仅保留「全部/成功/失败」，需在刷新时清理。
- **后端**：`GET /api/alarms/{key}` 已返回完整的 `NOTIFICATIONS`（含 `RESULT`、`MESSAGE`）及历史详情，统计与筛选可由现有数据计算，无新增接口要求。结果状态还包括 `Skipped`（层级结束时取消），见 `AlarmEngine.java` 中 `queue` / `dispatch`；「其他」由前端同时覆盖 `Pending`、`Skipped`。若后续需导出统计或分页，后端再评估聚合字段。
- 现有自动化覆盖：`frontend/src/components/__tests__` 尚无 `AlarmDetail` 用例，`backend/.../e2e/AlarmWorkflowE2ETest.java` 仅校验通知记录的 `Pending` 状态与 `Email` 渠道；新增筛选、刷新保留和空态建议补前端单元测试。
