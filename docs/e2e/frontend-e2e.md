# 前端 E2E 文本用例

被测对象：`frontend` 的生产构建（`frontend/dist`）在真实后端上的浏览器主流程。
Playwright 通过 `e2e/serve.mjs` 提供同源静态服务，并把 `/api/**`、`/health` 反代到临时后端，等价部署环境。

代码：`e2e/frontend/*.spec.ts`，公共登录/导航：`e2e/frontend/support/ams.js`，配置：`e2e/playwright.config.js`。
执行：`bash scripts/run-frontend-e2e.sh [spec 过滤]`（构建后端 jar 与前端、启动临时后端、运行 Playwright）。

## 公共前置

| 项 | 取值 |
| -- | ---- |
| 浏览器 | Chromium（`npx playwright install chromium`），视口 1440×900，语言 `zh-CN` |
| 后端 | 固定测试端口 18180（可用 `AMS_E2E_API_PORT` 覆盖），H2 临时文件库，`ams.scheduling=false`，SMTP 不配置 |
| 账号 | `E0043258` / `123456`（陈柏睿） |
| 数据 | 新增数据带唯一后缀；每个 spec 文件独立浏览器上下文 |
| 失败证据 | 截图、视频、trace 落在 `e2e/test-results/`，HTML 报告 `e2e/playwright-report/` |

## TC-FE-E2E-001 登录页加载与账号密码登入

**优先级**：P0　**代码**：`01-login.spec.ts`

| # | 步骤 | 预期 |
| - | ---- | ---- |
| 1 | 打开 `/` | 左侧品牌区可见；登录卡片标题“登入”；使用者代码预填 `E0043258`；密码为空 |
| 2 | 密码留空点击“登入” | 浏览器必填校验阻止提交，仍停留在登录页，未出现应用主壳 |
| 3 | 填错误密码提交 | 出现 `role=alert` 的错误提示并包含“账号或密码错误”，仍在登录页 |
| 4 | 正确账号密码登录 | 进入主壳（`.app-shell`），顶栏显示“陈柏睿”；标题“即时警报汇总”；侧栏含“测试告警触发”；顶栏“待我确认”；有“登出” |
| 5 | 点击“登出” | 回到登录卡片 |
| 6 | 重新登录后刷新页面 | 会话保持（`sessionStorage` token），仍显示主壳与“即时警报汇总” |

## TC-FE-E2E-003 厂别主档新增与隐藏

**优先级**：P0　**代码**：`03-master-data.spec.ts`

| # | 步骤 | 预期 |
| - | ---- | ---- |
| 1 | 登录 → 厂别管理 → “新增” | 出现“新增”弹窗（角色 dialog） |
| 2 | 填写唯一代码（`E2E...`）与名称 → “储存” | 出现“储存成功”提示；弹窗关闭 |
| 3 | 列表 | 30s 内出现该代码与名称的行，状态标签为 `Y` |
| 4 | 勾选该行 → “隐藏” → 确认弹窗“确定” | “储存成功”；默认列表不再包含该行 |
| 5 | 勾选“显示已隐藏资料” | 该行出现且状态为 `N` |
| 6 | 选中该行 → “取消隐藏” → 确认 | “储存成功”（可恢复） |
| 7 | 新增时使用已存在的代码 `Fab01` → “储存” | 服务端唯一键校验拒绝：不出现“储存成功”，弹窗保持打开；若出现错误区则内容含“唯一”（当前分支的 `state.error` 在对话关闭后不可见，用例同时断言无成功提示与弹窗保持打开） |

## TC-FE-E2E-004 测试告警触发、详情与确认入口

**优先级**：P0　**代码**：`04-alarm-workflow.spec.ts`

| # | 步骤 | 预期 |
| - | ---- | ---- |
| 1 | 登录 → “测试告警触发” | 页面警告“SMTP 尚未配置”；四个选择框（厂别/子系统/机台/警报代码） |
| 2 | 依次选择 `F01`、`SS03`、`EQP01`、`PRT_NODYE` | 子系统随厂别可选；警报代码列表非空 |
| 3 | 填唯一标题与内容 → “触发测试告警” | 出现“警报详情”弹窗，标题含唯一标记；副信息显示 `Fab01 / MES / PRT01`（厂别/子系统/机台的显示代码）；状态 `Process`；层级 `LEVEL-1 · 0 / 2 已回应人数`（邮件待发送） |
| 4 | 切换“详细内容”页签 | 显示正文；无“警报确认”按钮；提示当前账号暂无待确认操作 |
| 5 | 关闭详情 | 弹窗消失 |
| 6 | 直接打开 `/#/ack/not-an-existing-alarm` | 标题“邮件警报确认”；提示“打开邮件链接不会自动 ACK”；不自动弹详情 |
| 7 | 点“打开确认页” | 显示“警报不存在”错误（不自动确认） |

断言选择器说明：副信息使用厂别/子系统/机台的**显示代码**（种子：`F01=Fab01`、`SS03=MES`、`EQP01=PRT01`）。

## TC-FE-E2E-005 待我确认与告警列表联动

**优先级**：P1　**代码**：`05-alarm-list.spec.ts`

| # | 步骤 | 预期 |
| - | ---- | ---- |
| 1 | API 登录并读取即时汇总总警报数 | 200 |
| 2 | API 触发 `F01/SS03/EQP01/PRT_MOTOR_ERR` 测试告警 | 200，`ok=true`，`STATUS=Process` |
| 3 | 浏览器登录并进入顶栏“待我确认” | 标题“待我确认” |
| 4 | 列表内容 | 显示“查无资料”（SMTP 未配置 → 邮件未送达 → 无人可 ACK） |
| 5 | 重新获取 API token 后查询即时汇总 | 200；总处理中告警数 = 触发前 + 1 |

说明：浏览器登录会使同一账号的旧 token 失效（服务端单会话），因此步骤 5 重新登录取 token。

## TC-FE-E2E-006 无效警报查询与导出

**优先级**：P1　**代码**：`06-invalid-alarm-query.spec.ts`

| # | 步骤 | 预期 |
| - | ---- | ---- |
| 1 | API 触发 `MISSING_FACTORY/SS03/EQP01/PRT_NODYE` 与 `F01/SS03/EQP01/MISSING_ALARM`（标题带唯一标记） | 均 HTTP 422，`message` 分别为“未设定厂别”“找不到事件” |
| 2 | 浏览器登录 → 侧栏「查询报表」→「无效警报查询」 | URL `#/page/AVPA014`；标题“无效警报查询”；查询/汇出可见，重新整理置灰；提示“请执行查询” |
| 3 | 查询弹窗勾选「警报标题」包含唯一标记并查询 | 弹窗关闭；重新整理可用；`2 笔资料` |
| 4 | 表格内容 | 两行按资料时间倒序；分别显示“找不到事件”“未设定厂别”，厂别代码保留入参 `MISSING_FACTORY`，资料取得方式 `Mock` |
| 5 | 清除条件后仅按「资料时间」介于 `2000-01-01 00:00:00`—`00:00:01` 查询 | 表格空态“查无资料”，不报错 |
| 6 | 点击「汇出」 | 下载 `无效警报查询.xlsx`；表头为报表定义列标签（无效警报识别码/资料时间/失效原因/厂别代码…）；空结果不包含本次触发数据 |

说明：失效原因中“未设定层级1 / 未设定发送人员”需要改动事件层级主档，其落库由 `WorkflowIntegrationTest` 覆盖；其余
回落分支的 422 契约与落库、时间区间含端点、条件交集、倒序、未登录 401、汇出列在 `TC-API-E2E-006` 中验证。
