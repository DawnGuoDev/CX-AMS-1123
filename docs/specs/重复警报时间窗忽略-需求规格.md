# 重复警报时间窗忽略（Relative-Window Duplicate Suppression）需求规格

- 文档版本：v1（待评审）
- 仓库：`DawnGuoDev/CX-AMS-1123`（基线分支 `release`）
- 关联页面：AVMA009 警报通知设定、TEST 测试触发、AVPA013/004/007 报表
- 日期：2026-11-27

---

## 1. 背景与目标

AMS 当前已具备相对时间窗的重复警报抑制：在 `AlarmEngine.trigger()` 中，当同一四要素
（厂别 `FACTORY_KEY`、子系统 `SUB_SYS_KEY`、机台 `EQP_KEY`、警报代码 `ALARM_INFO_KEY`）
在上一条告警创建后的 `IGNORE_PERIOD` 秒内再次触发时，接口直接返回
HTTP 422 `{ok:false,message:'忽略相同警报'}`，**既不建立告警，也不留下任何记录**。

本次需求在**沿用相对窗口**模型的前提下做两点增强，并明确其与事件代码（`EVENT_KEY`）的搭配关系：

1. **静默记录但不通知**：时间窗内的重复触发不再被"无痕丢弃"，而是生成一条可查询的告警记录，
   但不进入层级通知（不发 Email、不排队、不升级、不需要 ACK）。
2. **可配置化**：抑制行为作为 AVMA009 警报通知设定上的字段维护，复用现有的四要素 + 事件配置。

### 用户选择（已确认）

| 决策点 | 结论 |
| --- | --- |
| 时间范围含义 | 沿用**相对窗口**（自上一条同要素告警起 N 秒），仅做可配置化/增强，**搭配事件代码使用** |
| 适用粒度 | 四要素（厂别/子系统/机台/警报代码），机台支持通配 `*` |
| 窗口内行为 | **静默记录但不通知** |
| 配置入口 | 并入 AVMA009 警报通知设定字段 |
| 交付范围 | 先出规格文档评审，确认后编码 |

---

## 2. 术语与匹配口径

- **四要素**：厂别、子系统、机台、警报代码。匹配顺序与现状一致：先精确 `EQP_KEY`，
  未命中再回退 `EQP_KEY='*'`；以最终命中的那条 `alarm_settings` 作为抑制判定依据。
- **事件代码（EVENT_KEY）**：AVMA009 每条设定绑定一个通知事件，决定层级、收件人、ACK/升级/重送策略。
  抑制窗口与行为都**依附在该设定（及其事件）上**，不单独新建实体。
- **相对窗口**：`IGNORE_PERIOD` 秒。判定基准沿用现状——同一四要素最近一条**已建立**告警的
  `CREATE_DT`。
- **抑制（Suppressed / logOnly）**：窗口内的重复触发，记录但不通知。

---

## 3. 功能需求

### F1. AVMA009 字段增强

在现有 `IGNORE_PERIOD`（忽略相同警报时间间隔，秒，默认 900，≥0 整数）基础上，新增字段：

| 字段（物理名） | 显示名 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `IGNORE_PERIOD` | 忽略相同警报时间间隔(秒) | number | 是 | `900` | 沿用现有字段；`0` 表示不抑制（每次都正常通知） |
| `IGNORE_ACTION` | 时间窗内重复触发处理 | enum | 是 | `SUPPRESS` | `SUPPRESS`=静默记录但不通知；`REJECT`=沿用旧行为直接 422 丢弃。用于兼容与灰度 |

> 说明：保留 `REJECT` 选项可让既有演示/测试需要"无痕拒绝"的场景不被破坏，默认值取 `SUPPRESS`
> 以符合本次需求。**该默认值与历史数据回填策略见 §7，请评审确认。**

校验（在 `Masters.validate` 的 `AVMA009` 分支补充）：

- `IGNORE_PERIOD`：整数、`≥0`（沿用现状）。
- `IGNORE_ACTION`：取值必须属于 `{SUPPRESS, REJECT}`；为空时按默认 `SUPPRESS` 处理。
- 事件归属校验（"通知事件不属于所选厂别／子系统"）维持不变，体现"搭配事件代码使用"。

前端 `metadata.json` 的 AVMA009 `fields` 增加一个 `select` 字段，`options` 为固定两项；
`defaults` 增加 `IGNORE_ACTION: "SUPPRESS"`。三语词典 `legacy-i18n.js` 增补标签翻译。

### F2. 触发时的抑制判定（核心）

`AlarmEngine.trigger()` 完成四要素匹配、事件/层级/收件人等现有校验后，按命中设定计算：

1. 读取 `IGNORE_PERIOD`（缺省 900）与 `IGNORE_ACTION`（缺省 `SUPPRESS`）。
2. 判定 `duplicate`：是否存在同一四要素、且 `now - CREATE_DT < IGNORE_PERIOD*1000` 的**已建立告警**
   （沿用现有谓词）。
3. 若 `duplicate`：
   - `IGNORE_ACTION=REJECT`：维持现状，返回 HTTP 422 `{ok:false,message:'忽略相同警报'}`，不写任何数据。
   - `IGNORE_ACTION=SUPPRESS`：执行 **F3 静默记录**，返回 HTTP 200（见 F5）。
4. 若不重复：维持现状正常建告警、起层级、排队发邮件。

判定基准保持"最近一条已建立告警"。被静默记录的抑制告警 `CREATE_DT` **也参与**后续窗口计算，
使持续重复触发在整个抑制期内始终只记录、不通知（详见 §4 边界讨论的待确认项 Q1）。

### F3. 静默记录但不通知（Suppressed 告警）

新增告警状态 `STATUS = "Suppressed"`，复用 `alarms` 表与现有四要素/事件快照字段：

- 写入 `alarms` 一条记录：四要素、`ALARM_INFO_KEY`、`EVENT_KEY`、`TITLE/CONTENT`、`PRIORITY`、
  `SOURCE_TYPE`、`RECEIVE_TYPE`、`CREATE_DT` 等照常填充。
- `STATUS="Suppressed"`；`FIRST_PROCESS_DT/LEVEL_PROCESS_DT/SEND_DT/LAST_ACK_DT/COMPLETE_DT` 置空；
  不设置 `CURRENT_LEVEL`/`ACK_REQUIRED`。
- **不**调用 `startLevel`：不写 `alarm_levels`、不写 `alarm_notifications`、不发送任何 Email、
  不产生升级/重送。
- 不要求也不允许 ACK；`enrich()` 中 `CAN_ACK=false`、`NOTIFY_COUNT=0`、层级相关字段为空。
- 写一条交易记录 `alarm_transactions`：`TRX_TYPE="Suppress"`、`STATUS_AFTER="Suppressed"`、
  `NOTE="忽略时间窗内重复触发，静默记录"`，含 `SNAPSHOT`，保证历史可追溯。
- 该类告警不进入 `dispatch()` 通知派发（无通知行天然不会被派发），调度器无需特殊改造。

### F4. 报表与查询可见性

静默记录需要"可查"，但不应污染待办与即时告警口径：

| 视图 | 是否包含 Suppressed | 处理 |
| --- | --- | --- |
| ACK_LIST（待确认，`/alarms/pending`） | 否 | `CAN_ACK=false`，天然被过滤，无需改动 |
| AVPA013 即时汇总 | **否（默认）** | 汇总只统计 `Process/Completed` 等在管告警；Suppressed 不计入未处理计数，避免误判 |
| AVPA004 处理查询 | 是 | 作为已发生记录可按条件查到，状态列显示"静默忽略/ Suppressed" |
| AVPA007 历史查询 | 是 | 通过 `Suppress` 交易记录可见，可看到每次被静默的时间与快照 |
| AlarmDetail 详情 | 是（只读） | 可打开，展示四要素/事件/内容/触发时间与"时间窗内重复触发，未通知"，无 ACK 按钮、无层级/通知区 |

> 是否在 AVPA013 提供"包含静默记录"开关，列为待确认项 Q2（默认：不包含，保持即时口径稳定）。

状态展示：前端 `state.js`/i18n 增加 `Suppressed → 静默忽略` 的状态标签与配色（中性灰/标签色），
详情页识别该状态隐藏 ACK 与通知面板。

### F5. 接口契约

`POST /api/alarms/test`（及设备模拟同入口）：

- 正常触发（不重复）：维持 `200 {ok:true, alarm, matchedBy}`，`alarm.STATUS="Process"`，无 `logOnly`。
- 重复且 `SUPPRESS`：

  ```json
  { "ok": true, "logOnly": true, "suppressed": true,
    "alarm": { "...": "enrich 后的 Suppressed 告警" },
    "matchedBy": "exact | wildcard", "message": "时间窗内重复警报，已静默记录，不发送通知" }
  ```

  HTTP 状态 **200**（成功受理，仅未通知）。`logOnly:true` 与现有 E2E 中
  `assertThat(...).doesNotContainKey("logOnly")` / `has("logOnly")` 的预留断言一致。
- 重复且 `REJECT`：维持 `422 {ok:false,message:'忽略相同警报'}`。
- 其它配置/校验失败（未设厂别、找不到事件、未设层级1、未设发送人员等）：维持 422，优先于抑制判定。

前端：

- 手动触发（`OperationsPage.submit`）：当返回 `logOnly`，提示"重复警报已在忽略时间窗内记录，未发送通知"，
  可打开只读详情；不再弹正常处理弹窗的 ACK 操作。
- 设备模拟（`DeviceSimulator`）：将"重复抑制"计数口径从"422 无痕"扩展为识别 `logOnly`，
  日志显示"重复触发已静默记录（未通知）"；`REJECT` 仍走现有 422 分支。

## 4. 关键边界与待确认项

- **Q1. 抑制基准是否包含 Suppressed 记录**：建议"包含"——持续抖动在整个时间窗内一直只记录不通知，
  窗口相对最近一次（含静默）触发滚动；窗口过后下一次恢复正常通知。另一方案是只相对"最近一条真正通知过
  的告警"，则同一抖动每隔一个窗口会再通知一次。**默认采用前者（滚动），请确认。**
- **Q2. AVPA013 即时汇总是否提供"包含静默记录"开关**：默认不包含，仅在 004/007 可见。请确认。
- **Q3. `IGNORE_ACTION` 历史默认值**：对历史 `alarm_settings` 行（无该字段）按 `SUPPRESS` 处理还是
  `REJECT` 处理？建议按 `SUPPRESS`（符合需求），但这会改变既有演示里"重复触发无痕 422"的表现。
  若需严格保持旧演示，可回填历史行为 `REJECT`、仅新建设定默认 `SUPPRESS`。**请确认。**
- `IGNORE_PERIOD=0`：不抑制，每次都正常通知（现状即如此）。
- 通配 `*` 设定下的去重键仍按"实际触发的具体机台号"参与四要素比对（与现状一致），即 `*` 仅用于匹配设定，
  不会把不同机台互相视为重复。
- 邮件语义不变：未生成通知行即不会发信；SMTP 成功/失败语义不受影响。

- 复用 H2 单行 JSON 快照（`AMS_STATE`），无新增表。
- `alarm_settings` 增加可空字段 `IGNORE_ACTION`；`metadata.json`/`seed.json` 同步：

- `alarms` 出现新状态值 `Suppressed`，无 schema 变更（状态为字符串字段）。
- `alarm_transactions.TRX_TYPE` 增加 `Suppress`。
- `meta.schema` 当前为 `checked-mvp-1`。本次为向后兼容的增量（旧快照缺字段按默认处理），
  采用与 `BYPASS` 清理相同的**启动期轻量迁移/容错读取**策略，不强制重建库；是否 bump schema
  在编码阶段按现状惯例处理。

## 7. 测试方案

后端（JUnit，`mvn -Pweb test`，沿用现有集成测试风格）：

1. `IGNORE_ACTION=SUPPRESS` 时窗口内第二次触发：返回 `ok:true,logOnly:true`，
   `alarms` 多一条 `STATUS=Suppressed`，`alarm_notifications` 数量不增加、无 Email，
   存在 `TRX_TYPE=Suppress` 交易。
2. 窗口过后触发恢复正常 `Process` 并发送通知（验证 Q1 滚动语义）。
3. `IGNORE_ACTION=REJECT` 时窗口内重复仍返回 422 且不建任何记录（回归现状）。
4. `IGNORE_PERIOD=0` 连续触发均正常通知。
5. 精确机台与 `*` 回退两种 `matchedBy` 下抑制均生效；不同机台不互相抑制。
6. Suppressed 告警：`/alarms/pending` 不出现；AVPA004/007 可查；详情 `CAN_ACK=false`。
7. AVMA009 保存校验：非法 `IGNORE_ACTION`、负数 `IGNORE_PERIOD` 被拒（沿用现有校验测试扩展）。
8. 重启持久化：抑制记录与设定字段在重新装载 `Store` 后仍存在。

前端（Vitest + Playwright，沿用脚本）：

- 主档表单出现枚举、默认值、保存回显。
- 手动触发与设备模拟在 `logOnly` 时的提示与计数；`REJECT` 仍走 422 文案。
- 报表中 Suppressed 状态标签与只读详情、无 ACK 按钮。

## 8. 验收标准

1. 可在 AVMA009 对每条四要素+事件设定配置 `IGNORE_PERIOD` 与时间窗处理方式，保存/回显/三语正常。
2. 时间窗内重复触发在 `SUPPRESS` 下生成可查询的 Suppressed 记录，**不发任何邮件、不进入待确认/升级**。
3. 窗口过后重复触发恢复正常通知；`REJECT` 与 `IGNORE_PERIOD=0` 行为符合 §3/§4。
4. 004/007 可追溯静默记录与 Suppress 交易，详情只读；ACK_LIST 与（默认）即时汇总不受污染。
5. 后端 `mvn -Pweb test`、前端 Vitest 与相关 Playwright 用例通过；README/PAGE_MAP 同步。
