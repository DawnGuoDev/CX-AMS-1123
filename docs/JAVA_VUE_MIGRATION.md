## 结构

Java 21、Spring Boot 3.5.7、Vue 3.5.46、Vue Router 4.5.1、Vite 6.4.6、POI 5.4.1。

| 文件/模块 | 职责 |
|---|---|
| `ApiController` | 登录、7 个配置页面、4 个报表、测试触发与 ACK；移除扩展接口 |
| `Masters` | 字段、唯一性、关联、层级、收件人与 ACK 人数校验、维护履历 |
| `AlarmEngine` | 四要素匹配、忽略重复、通知队列、ACK、失败重送与升级 |
| `SmtpDelivery` | SMTP 连接、认证/TLS、UTF-8 邮件及确认链接 |
| `EngineScheduler` | 每 2 秒推进告警与发送队列 |
| `Reports` / `Excel` | 固定报表、列条件、无效警报记录查询、汇总、Excel 导出/校验/导入 |
| `Store` | H2 持久化、单进程事务、隔离响应 |
| `metadata.json` / `seed.json` | 保留页面元数据与最小样例资料；不含模拟历史通知 |

## 通知与 ACK

每层 `USER_KEYS` 直接保存通知人员。层级必须从 1 连续；每层至少一位启用且有邮箱的人员；所需人数为 `0`、`*` 或不超过通知人数的整数。升级间隔单位为分钟，失败重送间隔为秒。

触发时先匹配指定机台，再匹配 `*`；同机台群组回退和机况抑制已删除。厂别、子系统对应、机台、告警配置和事件必须有效。相同四要素在忽略间隔内返回 422。子系统仅维护代码与名称，新告警统一进入层级通知流程。

告警记录在创建时保存层级定义快照，配置修改不会删除运行中告警的后续层级。每层启动时解析启用人员并生成持久 `Pending` 邮件。单个后台派发器按告警优先权从大到小取最多 20 封，SMTP 网络操作在 Store 锁外执行；连接、读写超时均为 5 秒。结果记录为 `Success` / `Fail`，已结束层级尚未发出的邮件标记 `Skipped`。

重试只针对各收件人本层级最新一次 `Fail`，按实际失败时间、间隔与次数限制，不重发 `Success` 邮件。只有本层级邮件已被 SMTP 接受的人员能 ACK；每人每层一次。普通 ACK 达标关闭告警；零 ACK 等待邮件均发送成功后完成，失败仍按规则重试/升级。`*` 按该层启动时的有效人员数计算。

邮件包含 `AMS_PUBLIC_URL/#/ack/:alarmKey`。打开链接不会修改状态。未登录时显示登录页，登录后回到该告警；POST ACK 重新验证当前账号、层级和处理状态。

SMTP 服务器接受邮件后、结果写回 H2 前若进程异常，重启可能再次发送这封 `Pending` 邮件。当前是单机持久队列，不承诺邮件恰好发送一次。SMTP 接受不等于最终投递回执。

## 主档与报表

- 复制清空唯一代码；编辑代码只读。后端再次校验唯一性与关联、通知人员及人数。
- 隐藏/恢复及配置变更记录履历，事件履历包含层级和人员变化。
- 使用者补中间名、IPPhone、警报联系电话、到职日、员工标记。新增密码必填，修改留空保持旧密码，复制不携带密码；导出和履历不泄露密码。
- 资料列表补修改时间／人员代码／名称；履历记录请求 IP，浏览器无法取得的客户端电脑名称留空。
- 一般主档和对应关系保留既有 Excel 流程；事件主从档使用页面维护。主档 Excel 流程扩展不在本轮范围。
- 事件编辑锁定代码、厂别与子系统；主要资讯／清单资讯分签，层级确认加入暂存，最终保存才持久化。层级、分钟、次数、秒数校验整数，连续层级错误不自动重排。
- 汇总仅统计 `Process`，10 秒刷新，可下钻到机台。
- 处理/历史查询按启用列条件取交集；文本支持包含、不包含、开头、结尾、等于、不等于；日期支持等于、不等于、大小比较、区间。
- 测试触发失败在同一写事务内追加 `invalid_alarms`，保留 422 响应契约；记录 8 种可判定失效类型、当时主档/事件上下文和重复警报 key。查询必须指定 `CREATE_DT` 时间区间，默认近 24 小时，可条件过滤与导出。旧快照启动时幂等补齐集合、报表定义和菜单，不升 schema。
- 处理／历史查询初始不请求结果；条件弹窗取消丢弃草稿，未勾选输入禁用，列过滤取交集、可重置。日期时间查询与过滤精确到秒。
- 历史查询至少启用一个有值条件；新交易保存当时告警状态、时间及层级／通知／ACK 快照；点击修改时间打开所选交易详情。旧交易未保存的可变计数留空，不把当前状态冒充历史；完全缺少资料快照的旧交易不能还原详情。
- Excel 导出当前已查询并列过滤的结果；无资料仍输出表头。汇总下钻保留厂别／子系统／机台代码名称并使用相同导出列。
- 待确认通过详情单笔提交，后端检查当前人员与层级权限；告警详情分基本资讯／详细内容／回应备注，切换告警清空旧备注。

## 数据与本地部署

默认数据库改为 `backend/data/ams-mvp`，保留旧版数据文件原样。Schema 标记为 `checked-mvp-1`，如果显式指向旧数据库则拒绝加载，避免把旧模拟任务当作真实 SMTP 队列。登录 session 在内存中，重启需重新登录。

启动入口为 `scripts/start-java.sh`，读取不入 Git 的 `.env.local`。正式配置示例为 `.env.example`。构建入口为 `scripts/build-java-vue.sh`；打包前必须构建 Vue 并使用 Maven `-Pweb`。

启动脚本使用 SHA256 命名的 `.runtime` 不可变 JAR，避免开发时 Maven 覆盖活动文件导致延迟类加载失败。当前 schema 内的旧持久数据继续保留；报表元数据读取时补齐新增固定列，不需要删除数据库。升级前已备份当前 H2 文件。

当前验证环境为单机 H2 `AMS_STATE` JSON 快照，非关系型生产表模型；没有多副本调度、租户隔离或细粒度 RBAC，登录用户可以维护配置。此轮没有引入未勾选的数据库架构和权限系统。
