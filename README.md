# AMS 警报管理系统（本地可运行版）

以《AMS 背景介绍和名词解释》《AMS 架构图》《AMS 使用者操作手册》《AMS 系统需求》《AMS 系统页面功能汇整》五份资料为依据，在本地还原的一套可点击、可流转的 AMS（Alarm Management System）Web 应用。

系统覆盖从主档维护、事件与层级设定、警报通知设定，到警报补登／手动发送、多通道派发、层级升级、确认／中断，再到即时汇总与历史报表的完整闭环。

- 页面与功能映射：[PAGE_MAP.md](./PAGE_MAP.md)
- 技术栈：Node.js + Express 5 + JSON 文件资料库 + 原生 ES Modules 前端（无构建步骤）
- 不需要 Oracle、Redis、MQ 或任何外部服务即可运行

---

## 一、快速开始

### 环境要求

- Node.js **20 或以上**（已在 Node.js 24 上验证）
- 现代浏览器：Chrome / Edge / Firefox

### 启动

```bash
cd Changxin-AMS
npm install
npm start
```

打开 <http://localhost:3000>。

首次启动会自动建立 `data/db.json` 并写入种子资料（3 个厂别、6 个子系统、12 台机台、12 位使用者、6 个事件、8 条警报通知设定、40 余笔历史警报、10 类无效警报、装置状态与报表定义）。

### 重置演示资料

```bash
npm run reset
# 重新启动服务
npm start
```

> 演示时钟持续运行；若放置过久，种子中的处理中警报会依真实时间升级或失败，重置即可恢复初始状态。

### 指定端口

```bash
PORT=8080 npm start
```

## 三、建议体验路径

### 1. 警报补登 → 通知 → 确认（核心闭环）

1. 以 `E0043258` 登录。
2. 进入 **ALM → 警报作业 → 警报补登作业**。
3. 厂别选 `Fab01`，子系统选 `MES`，机台选 `PRT02`，警报代码选 `PRT_MOTOR_ERR（群组回退）`。
4. 填写标题与内容，按「发送」。
   - 系统会依四要素寻找警报设定；PRT02 无独立设定，自动回退到同群组 `$PRT` 中 PRT01 的设定。
   - 依事件层级派发 Email／SMS／IM（模拟通道）。
5. 在结果弹窗点「开启确认页」，或点右上角铃铛打开 **通知收件箱**。
6. 在确认页填写回应备注，点「警报确认」。
   - 印刷机事件 LEVEL-1 需要 2 人回应；第一位确认后显示 `1 / 2`，警报仍为处理中。
   - 换另一位 LEVEL-1 成员（如 `E0043260 / 123456`）确认后，状态变为 `Completed`。

### 2. 观察层级升级与失败

1. 在右上角把 **演示时钟** 从 `×1` 调到 `×60`（资料中的 10 分钟升级间隔会换算为 10 秒）。
2. 重新补登一笔印刷机警报，等待约 10 秒：LEVEL-1 未达回应人数，自动升级到 LEVEL-2（主管）。
3. 再等待约 20 秒：若无下一层级且无人回应，状态变为 `NoNextLevel`（失败）。
4. 随时可在警报详情抽屉的「交易履历」查看 `Create → Modify → LevelUpgrade → AlarmFail` 全过程。

### 3. 设定链

按手册顺序走一遍：

```
子系统设定 (AVMA003)
→ 厂别子系统对应 (AVMA004)
→ 事件通知人员群组 (AVMA006)
→ 事件通知 + 层级 (AVMA007)
→ 事件层级与群组对应 + 渠道 (AVMA008)
→ 警报通知设定 (AVMA009)
→ 警报补登验证 (AVPA009)
```

其中：

- **AVMA006** 用「主要资讯 / 列表信息」双页签，列表信息是人员穿梭框。
- **AVMA007** 的层级代码必须从 1 开始连续；可在列表信息中新增／删除层级。
- **AVMA008** 左侧为「事件 → LEVEL-n → 群组」树；可右键层级新增群组对应，右键群组修改／移除；保存后整棵树写入。
- **AVMA009** 四要素组合唯一；可只填 `*` 表示任一机台。

### 4. 报表

- **即时警报彙整**：10 秒自动刷新，可进入某厂别 × 子系统查看各机台警报数。
- **警报处理查询**：默认近 7 天，可导出 Excel。
- **历史纪录查询**：至少选择一个条件；点击任一笔可打开完整交易履历。
- **无效警报查询**：查看 10 类失效原因。
- **系统装置状态查询**：Agent 汇总，展开可看装置明细与收发计数。

### 5. 汇入／汇出

- 任一主档页支持「汇出」「汇出范本」「汇入」。
- 汇入流程：选择 `.xlsx` → 验证 → 逐行显示可汇入／错误讯息 → 勾选后汇入。
- 地图型（Mapping）页面另外支援主档代码 + 对应代码的扁平范本。
- 自动切机况与事件层级树使用 CSV 作为批次交换格式。

## 五、技术说明

### 架构

```
public/ (原生 ES Modules + CSS)
        │ fetch /api
        ▼
server.js (Express 5)
   ├── src/auth.js          会话与 SSO
   ├── src/api.js           REST API
   ├── src/db.js            JSON 资料库（原子写入）
   ├── src/seed.js          种子资料
   ├── src/metadata.js      通用主档／Mapping／MasterDetail 元数据
   ├── src/master-service.js 通用 CRUD、唯一键、履历
   ├── src/alarm-engine.js  警报匹配、派发、升级、重送、ACK、中断、自动切机况
   ├── src/reports.js       报表查询与仪表板资料
   └── src/excel.js         Excel 汇出／范本／汇入验证
```

### 关键设计

- **通用框架页**：一般主档、Mapping、MasterDetail 由同一份元数据驱动；新增主档只需增加配置。
- **警报状态机**：`Process → Completed / NoNextLevel / Terminated`；另有 `LogOnly`（子系统 BYPASS）与 `NoNotify`（无效警报）。
- **四要素匹配**：厂别 + 子系统 + 机台 + 警报代码；精确匹配失败时依机台群组回退。
- **忽略重复**：依 `IGNORE_PERIOD` 过滤，写入无效警报。
- **机况抑制**：CVMA011 设定机台型号 × 机台状态；命中时写入「在某机况下无需发送」。
- **层级升级与重送**：依事件层级的回应人数、升级间隔、失败重送次数／间隔执行；每次变更写入交易履历。
- **通知通道**：Email／SMS／Phone／Voice／IM 等以本地模拟方式派发，检查使用者联络资料与装置状态，失败原因会记录在通知纪录中。
- **装置计数**：模拟发送会累计各装置的接收／成功／失败数量，并可在 AVPA015 启停。
- **自动切机况**：规则匹配近期警报，自动切换机台机况（可选联动 Chamber），每 5 分钟扫描，也可手动扫描。
- **演示时钟**：预设 `×1`，可切换 `×10 / ×30 / ×60`。资料中的分钟／秒不会被改写，仅影响引擎的时间换算，便于观察升级与逾时。
- **三语**：简体中文为基底，English 使用词典，繁體中文使用 OpenCC 即时转换（UI 文案；使用者资料保持原输入）。
- **资料保存**：写入 `data/db.json`（先写临时文件再重命名，避免半写入）。没有外部依赖。

## 七、已知限制（本地演示版）

1. **通知为模拟通道**：不会真的发送 Email／短信／语音／飞书；通知会出现在右上角「通知收件箱」，可打开确认页。
2. **AVMA010（触发条件）的 SQL 不会实际执行**；「测试 SQL」会做语法结构与栏目解析并回传模拟结果，条件定义会保存。
3. **RPTSET001（报表设定）的 SQL 不会实际执行**；报表页使用内建资料集。修改「查询条件」与「栏位资讯」会影响对应报表页的查询条件与呈现，图表／枢纽等进阶设定会保存为定义。
4. **权限为演示级**：登录后可访问全部页面；使用者群组与对应关系已建置，但未实作细粒度 Action 权限拦截。
5. **JSON 单档资料库**：适合本机演示，不建议多实例并发写入。
6. **单一会话与 30 分钟闲置逾时**：服务重启后记忆体中的会话会失效，需要重新登入。
7. 种子资料中的「处理中」警报会随时钟持续流转；若想回到初始状态，使用 `npm run reset` 并重启。

## 八、常见问题

**Q：启动时报 `EADDRINUSE`？**  
端口 3000 被占用。使用 `PORT=3001 npm start`，或关闭占用程序。

**Q：登录后马上被踢出？**  
同一账号在另一个窗口登入会踢出旧会话（SSO 设计）。重新登入即可。

**Q：为什么警报没有出现在「确认回报作业」？**  
该页只显示「目前层级实际通知给您」且您尚未确认的警报。若已升级到下一层级，需由下一层级成员处理；可由通知收件箱打开确认页查看。

**Q：演示时钟调快后资料变很多？**  
这是引擎在加速时间下的正常行为。重置资料即可恢复。

**Q：可以修改种子资料吗？**  
可以。`src/seed.js` 为种子生成逻辑；修改后执行 `npm run reset` 并重启。日常操作产生的资料直接保存在 `data/db.json`。
